# 回响深渊 · Echo Abyss

融合 **挂机放置 + 暗黑Like装备驱动 + 吸血鬼幸存者Like尸潮割草** 的自动化构筑类游戏。
本仓库实现策划案(《回响深渊_完整游戏策划案.docx》)的核心循环,并已落地《docs/DESIGN-V3.md》赛季结构(赛季壳/章型差异化/三阶段 Boss/跨套组合技/竞技场地形/幻影榜)。

## 快速开始

```bash
npm install
npm run dev        # 开发服务器 → http://localhost:5173(从主菜单进入)
npm run test       # 单元测试(vitest,词缀引擎 + 各系统 + 平衡模拟)
npm run build      # Web 生产构建 → dist/

npm run sync:cocos       # Web 共享层 → cocos/assets/scripts/game 单向同步(只新增与覆盖)
npm run build:cocos      # Cocos Creator 3.8.8 构建 → cocos/build/web-desktop
npm run smoke:cocos      # 构建产物冒烟(产物齐全 / 引擎自举 / 16 屏节点在位 / 无越白名单异常)
npm run typecheck:cocos  # Cocos 侧类型检查(基线 0 条)
npm run serve:cocos      # 起构建包静态服务 → http://localhost:4173
npm run dev:lab          # 主菜单布局台(dev-only,拖拽导出 balance.json 的 menuLayout / menuSkin 段)

npm run build:minigame && npm run smoke:wechat   # 构建微信小游戏包并冒烟测试
```

**两棵树并存**:`cocos/assets/scripts/` 是现役实现(渲染层 + 屏层 + 宿主),`src/` 是 Web Canvas 基准树(迁移期的逐屏对照物,渲染代码冻结);两边共用的纯逻辑与数值表只有一份,住在 `cocos/assets/scripts/game/`,经 `@game/*` 别名同时被两端 import。Cocos 侧的逐屏对照与验收口径见 `docs/COCOS-MIGRATION.md`,像素皮肤与资产产线见 `docs/UI-PIXEL-REFRESH.md`。

**微信小游戏**:`minigame/` 目录是完整工程,用微信开发者工具导入即可运行(游客模式);详见 `docs/PORTING-WECHAT.md`。当前 `npm run build:minigame` 走 `vite.config.minigame.ts` 的 `entry: "src/main.ts"`,即打出的是 Web 基准树;Cocos 侧的 `wechatgame` 平台构建尚未接(本机无微信开发者工具),这条挂在 `docs/COCOS-MIGRATION.md` 的 Phase 6。

**UI 设计**:`docs/UI-DESIGN.md` 为完整设计规范(色彩/字体/组件/界面线框/动效),主题令牌落地于共享层 `cocos/assets/scripts/game/ui/theme.ts`。

**策划配置表**:核心数值平衡(体力/经济/章节曲线/生成节奏/章型/扭蛋 + 主菜单布局与皮肤)外置于 `public/config/balance.json`,改完刷新即生效;字段说明见 `docs/CONFIG-TABLES.md`。加载是双通道同一份文件:Web 侧 `src/platform/balance.ts`,Cocos 侧 `cocos/assets/scripts/core/ConfigChannel.ts`(校验 + 非法回退默认,控制台告警),测试 `tests/balance-config.test.ts`。

**美术贴图皮肤**:清单 154 键(`cocos/assets/scripts/game/data/assets.ts`),`public/assets/` 实有 152 张 —— 4 枚键在册待出图(`slot_skill` / `bar_capsule` / `joy_base` / `joy_knob`),2 张图待登记(`gen-entry-gearup` / `gen-badge-gear-lv`)。按钮板/面板底垫/头像框/星图标/血条/特效等贴图优先(`game/ui/skin.ts` + `drawNine` 九宫格),缺图自动回退代码绘制,布局与命中区域不随皮肤改变;Cocos 侧像素皮肤与产线见 `docs/UI-PIXEL-REFRESH.md`,映射见 `artwork/MAPPING.md`。

**画面适配(竖屏全量翻版 v2)**:UI 按 **560 宽设计空间**布局(字阶/控件档位集中在 `cocos/assets/scripts/game/ui/theme.ts` 设计令牌),设计高随屏幕比例伸展 `clamp(996→1246)`——**手机竖屏(如 1080×2340)顶满无黑边**,桌面(1920×1080)为居中 9:16 列 + 场景背景满溢底。战场恒为 560×996 标定空间(战斗 HUD 为上下双坞,高屏多出的部分是底坞之下的歇指区;刷怪节奏为绝对时间制,不随屏幕尺寸稀释);触摸/点击坐标统一换算回设计空间,命中与绘制像素一致。

## 玩法结构(需求优化 v2:赛季关卡式 × 场内肉鸽 × 场外养成)

- **主菜单**:主线关卡列表 + 无限关 + 英雄展示带(选英雄即定本命节律与初始基调)+ 7 枚场外入口(委托 / 扭蛋 / 天赋 / 通行证 / 每日 / 升级 / 融合);Web 基准侧另有快捷键 1-7 / E / G / T / P / C / U。
- **主线关卡(7 关 × 20 章)**:每关 20 章 × **60 秒**限时生存,每章**一屏竞技场**(全屏可见,无镜头移动);关底结算:**7 关第 20 章均出 Boss,杀 Boss = 通关,超时未杀判负**;偶数关(2/4/6)Boss 为**弱化变体**(血量 ×0.7、跳过二阶段、死亡不分裂);章间**商店**(金币买卡,玩家手动开始下一章)。通关解锁下一关,回响奖励随关卡递增(10×N^1.5)。
- **自主控制(挂机)**:角色默认自动移动(贴身才躲、平时巡场)+ 全自动战斗/拾取,手动输入可接管;F6 切换挂机/手动,HUD 显示状态。
- **英雄节律 × 独有技能 × 法宝(`docs/DESIGN-HERO-RHYTHM.md`)**:触发条件不再是卡上的随机词条,而是**英雄本命节律**(受击/周期/击杀/移动/连杀/低血,12 英雄各 2 人);**升级三选一**只发**英雄独有技能**(核心 1 + 互斥分岔 2 + 进阶 1,各 5 阶;分岔选中即解锁第 2 节律;每章 1 次免费重随、锁 1 张;技能池耗尽出兜底);**章间商店**只卖**法宝**——主动法宝 14 = 现效果层(不带修饰器,挂在已解锁节律上发动,点行可切节律,挂到共鸣节律上改名变形)、被动法宝 8+2 = 现修饰器层升格为全局乘区(被动槽 4,同款叠加按 0.6 递减);进第 1 章前**首章法宝三选一**(免费,至少 1 张共鸣)。**共鸣**是质变点:法宝挂到共鸣节律上、技能拿到共鸣被动都会改名变形,首次达成有横幅 + 0.4s 时停并入图鉴;本局共鸣 2 / 4 处激活原套组两档联动加成(套装件数退役)。**赛季共鸣**(R5):S2 起每季 3 对新「法宝 × 节律」共鸣格 + 1 枚赛季法宝(霜牢符 / 熔核符 / 招魂符,当季商店偏向、过季常驻),过季新格降为回响共鸣(改名保留、补丁减半);发现横幅带「本季新共鸣 / 回响共鸣 / 本季首发」角标。被动池另含 8 枚**遗物**(命运骰 / 裂核 / 沙漏 / 透镜 / 稳定器 / 磁轭 / 护心镜 / 假命,修饰器 : 遗物 = 2 : 1)。升级弹层可花金币**重置分岔**(每局 1 次)。各英雄核心技能按旧武器射速带**节律调率**(凯尔 / 诺拉 1.2s 齐射、洛卡 3 连杀、多兰 168 步、希雅七成血),事件节律核心另带 3s **底拍**保证冷启动。**界面两列表**:战斗 HUD 底坞上排独有技能、下排主动法宝(排间分隔线),章间商店在槽位钮下方多一段只读「独有技能」行(名 / 类别 / 节律 / 阶数)。**召唤物跨章保留**:骷髅 / 狼 / 亡影随主人进下一章,剩余存活照常倒数。**精英章**(5 / 10 / 15)章首 6 秒只有密度,第 6 秒起精英入场并打横幅。HUD 每张卡底两条细条:CD 条(周期 / 底拍)与节律进度条(连杀 / 移动 / 低血攒到几成)。跨局:该英雄任一关 3 星通关解锁**第二本命**,英雄页第 4 行点行切换,开局核心技能与挂机档随之切换。S1 三英雄 + S2 三英雄(希雅 / 诺拉 / 洛卡)有专属技能表,其余走通用职业包。
- **场内金币经济**:杀怪掉金币;章间商店买法宝(主动槽基础 4,天赋最多 +2、本局广告 +1,硬顶 6;被动槽 4,天赋「被动槽扩展」+1),价格随购买数与章节递增;**场内成长双轨**:强化(任意法宝金币升级,数值增长)+ 进化(2 张同款升档,形态变化;3 张免费);等级每级 +8 最大生命;攻击射程 640 覆盖全屏。
- **荆棘反伤回血流(受击类联动)**:受击/受伤触发卡 + 吸血/汲取/护盾回血来源 同时在场时激活——每次挨打回 2% 生命,受击/受伤触发的效果伤害 +50%;商店会配对互补卡引导凑齐流派(有荆棘补回血、有回血补荆棘),HUD 显示"荆棘回血"提示。
- **武器套组(12 套 = 12 英雄的包装层)**:套组仍是**效果派系**——商店卡池偏向(常驻 60%、当季 70%)与卡面"套"角标的依据;派系划分冻结,新效果只做纯追加归属。场外入口由"选套组"改为**选英雄**(见上条),12 套由 12 位英雄一一对应包装(常驻 3 + 赛季限定 9,按 `releaseSeason` 2/3/4 分批上市)。原 3 / 6 件联动数值保留、**触发条件改读本局共鸣数**(2 / 4 处,`RESONANCE_TIERS`),套装件数计数已退役;开局基调来自英雄核心技能(荆棘圆环·受击爆发 / 寒霜齐射·全屏减速弹幕 / 连闪天火·闪电连锁 / 极北权杖·霜环扩散 / 熔核之心·陨星落点 / 影群哨笛·灵狼协战 …)。
- **赛季新鲜感三层(DESIGN-SEASON-SETS,`cocos/assets/scripts/game/data/seasonSets.ts`)**:① **L1 主题**——4 主题循环(回响苏醒/永冻深渊/熔火回响/幽冥潮汐),带主题色与 `envBias` 环境词缀加权;② **L2 赛季联动词缀**——常驻三套各 5 条 mutation 池按 `pool[(seasonId-1)%5]` 轮换,±15% 内的 stat 级 patch 走 `ctx.setBonus` 实时折入,并定向商店首个修饰器;③ **L3 赛季限定套组**——frost/magma/phantom 按 `releaseSeason` 2/3/4 上市,当季商店偏向 60%→70% + 双 patch 专属词缀,过季永久保留可选但加成自动回落。全部为 `seasonId → 纯函数`(同赛季恒同配置),只作用玩家侧、不折入怪物曲线。
- **章节敌情(克制导向)**:每章 4 类敌情轮转(尸潮/重甲/异变/精英),HUD 与商店显示"敌情+推荐套组";本章主力敌种更频繁出现且 +40% 血量,不针对就压力陡增。
- **首局引导**:新玩家第 1 关自动弹出 6 步顺序教学(自动挂机→金币→买卡→套组→强化与进化→章节/敌情),每条 8 秒自动隐藏,可点「跳过」永久关闭(存档 tutorialDone)。

## 操作

- **桌面端**:WASD / 方向键移动(默认挂机自动移动,手动输入即接管);攻击完全由装备的自动化规则执行(策划案 2.3)
- **移动端**:屏幕左半区拖动虚拟摇杆
- **章间商店**:每章 60 秒结束后进入商店——金币买卡/强化/进化/购槽,Enter 或点按钮开始下一章
- **阵亡/通关**:结算回响点数与星数(通关),返回主菜单;阵亡可选看广告复活(每局 1 次)
- **天赋树界面**:点击节点购买(需满足层级解锁),配置定向搜索/完美蓝图后开始新对局

## 已实现(核心循环 MVP)

> 本节记的是 MVP 期的引擎面貌(触发器 × 效果 × 修饰器三合一卡、4 档品质)。此后装备系统重构与英雄节律重构把这三层拆成「本命节律 / 独有技能 / 主动 + 被动法宝」,现为 **6 节律 × 14 主动法宝 × (8 + 2) 被动法宝 + 8 遗物**、品质 5 档(含隐藏)——当前口径见上文「英雄节律 × 独有技能 × 法宝」与 `docs/DESIGN-HERO-RHYTHM.md`。

- **装备词缀引擎**(策划案 3.2/3.3 全量):

## 架构

```
cocos/assets/scripts/        # 现役实现(Cocos Creator 3.8.8)
├── Bootstrap.ts / GameShell.ts   # 引擎自举 + 宿主(路由/广告唯一入口/弹层与覆盖层接线)
├── core/                    # ScreenRouter(16 屏)/ SaveModel / ConfigChannel / AdChannel / ViewTable
├── game/                    # 共享纯逻辑层(唯一事实源,两端共用,禁 cc 与 DOM)
│   ├── data/                # rhythm / heroSkills / artifacts / equipmentGen / sets / seasonSets
│   │                        #   chapters / stages / intel / season / leaderboard / daily / talents ...
│   │                        #   以及 assets.ts(贴图清单)/ pixelArt.ts(像素档与九宫格键表)
│   ├── systems/             # equipmentEngine(节律与共鸣引擎)/ battleWorld(世界)/ waves / onboarding
│   ├── entities/ + ui/      # player / enemy / projectile / objects;theme / skin / hud / shop / layout
│   └── dev/                 # 布局台模型(dev-only,不进构建包)
├── battle/ heroes/ shop/ …  # 每屏一对:cc-free 的 *Model(账本 + 命中) + *View(节点层)
└── levelup/ menu/ pass/ …   # 同上分层

src/                         # Web Canvas 基准树(迁移期逐屏对照物,渲染代码冻结)
└── game.ts + platform/ + ui/ + systems/ …
tests/                       # 69 个测试文件(引擎/各系统/布局几何/像素产线/平衡模拟)
scripts/                     # balance-sim / sync-cocos / cocos-typecheck / smoke-cocos / pixel-kit …
```

**设计要点**:

- 数值与纯逻辑只有一份,住在 `cocos/assets/scripts/game/`,经 `@game/*` 别名同时被两端 import;`tests/shared-purity.test.ts` 守着这条边界(共享层禁出现 `cc`、`CanvasRenderingContext2D`、`window/document/localStorage/requestAnimationFrame` 等)。
- 词缀引擎只通过 `BattleContext` 读写世界,不碰渲染与平台 API,可独立单测。
- 实体数组用**原地修改**(`removeIf`)清理,不用 `arr = arr.filter(...)` 重新赋值——BattleContext
  持有数组原始引用,重新赋值会导致引擎看到陈旧数组(飞刀打不进新数组、引擎看不到新敌人)。
- 屏层的分工是「模型算账与命中、视图只摆节点」:几何一律转调 `game/ui/*Layout.ts` 的纯函数,绘制与命中同源同一份矩形。
- 开局输出由英雄本命节律 + 核心技能给出;事件型节律另带一条慢周期「底拍」,保证不依赖击杀即可破局。
