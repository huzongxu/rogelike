## 0. 一句话

**每局第 2 章选一条路，第 4/8/12 章各选一枚节点；分岔技能是这条路的主动件，核心 `coreMorph` 承载路线主循环，节点改主循环的规则。** 三层节点 = 2³ = 8 种组合，选择发生在挑战之前。

## 1. 结构

保留现行四技能底子（核心 1 / 互斥分岔 2 / 进阶 1），在其上追加一层**章节节点**。分岔与节点的区别：

| 层 | 时机 | 形态 | 占槽 | 重随 / 锁定 | 落点 |
| --- | --- | --- | --- | --- | --- |
| 核心 | 开局 | 自动携带 | 不占 | — | `HERO_SKILLS[hero].core` |
| 分岔 | **第 2 章开章** | 二选一，本局锁定 | 不占技能槽 / 商店槽 | 不可 | 分岔技能 + 该分岔 `coreMorph`（主循环） |
| 节点 | **第 4 / 8 / 12 章开章** | 每层二选一，层内锁定 | 不占 | 不可 | `HeroNodeDef.patch` 并入核心 / 分岔施放 |
| 进阶 | 普通升级三选一 | 与其他技能同池 | 不占 | 可锁 1 张 / 每章免费重随 1 次 | `HERO_SKILLS[hero].advance` |

**普通升级节奏本批不动**：仍按玩家等级发三选一，每章约 2.5–3 轮；「每章一次普通轮」属于 CR-01，见 §8。

## 4. 数据与解释

### 4.1 表

新增 `cocos/assets/scripts/game/data/heroBuild.ts`（唯一出处）：

```ts
type BuildTier = 1 | 2 | 3;                 // 第 4 / 8 / 12 章
type BuildSide = "a" | "b";

interface HeroBuildProfile { heroId: HeroId; branchChapter: 2; nodeChapters: [4, 8, 12]; }
interface BuildBranchDef { id; heroId; side; skillId; name; desc; loop?: BranchLoopPatch; }
interface BuildNodeDef { id; heroId; branchId; tier; option: 1 | 2; name; desc; patch: BuildPatch; }
type BuildStep =
  | { kind: "branch" }
  | { kind: "node"; tier: BuildTier };
```

`BuildPatch` 按主循环分组，字段全部可选：`nova`（盾 / 直线 / 反刺 / 截阵 / 城垣）、`trail`（扎根 / 播种 / 接续 / 折枝 / 花圃 / 孤花）、`fan`（折返 / 交织 / 旋转 / 拦网 / 两波 / 前后半圆）、`mark`（接印 / 侧晶 / 折射 / 定焦 / 贯线 / 定格）、`wolf`（夹猎 / 护主 / 焦点 / 截击 / 猎线 / 返扑）、`shade`（巡演 / 定场 / 连线 / 聚场 / 返照 / 定格）。未知键在加载时拒绝，不静默覆盖。

### 4.2 合并顺序

1. 分岔技能自带 `coreMorph`（路线主循环配置）；
2. 本局已选节点按层序并入（第 4 → 8 → 12）；
3. 共鸣 `resonanceMorph` 最后并入。

同键冲突按「后写覆盖」；分支 / 节点 / 共鸣各自只写自己的键，不写对方。`branchChosen` 仍只用于发牌互斥，战斗差异全部由技能是否在包 + morph 决定。

## 5. 生命周期

| 事件 | 分支 / 节点 | 临时资源 | 说明 |
| --- | --- | --- | --- |
| 第 N 章开章 | 挂起待选，选完写入 | 清空 | 开章冻结世界；商店仍在上一章末 |
| 换章 | 保留 | 清空 | 层数 / 标记 / 未兑现 / 配对缓存全部清 |
