# 主菜单布局台 · LAYOUT-LAB

> 目的:把"往左一点"这种话变成一次拖拽。所见即所得地调主菜单布局与皮肤,**不改源码、不落盘**,唯一产出是 `menuLayout` / `menuSkin` 两段 JSON。
> 启动:`npm run dev:lab`(= `vite --open /layout-lab.html`,起 dev server 并自动打开)。已有 dev server 在跑时,直接访问 `http://localhost:5173/layout-lab.html`。
> 代码:`src/dev/layoutWorkbench.ts`(DOM/输入)+ `src/dev/labModel.ts`(布局纯函数层)+ `src/dev/labSkin.ts`(皮肤纯函数层,均有单测覆盖)+ 页面 `layout-lab.html`。
> **dev-only**:这四样文件不在 `index.html` 的构建图里,也不被 `src/main.ts` 引用 → 生产包 `dist/` 与小包体 `minigame/js/game.bundle.cjs` 均不含(验收见文末)。

## 三条不可让步的设计

1. **底图就是真游戏。** 布局台实例化真实 `Game`,它的 RAF 每帧用 `snapshotMenuLayout()` 重画 `drawMenu`;浮层几何读同一个 `game.menuLayout()`。所以"看到的框"必然等于"画出来的东西",不存在第二套布局实现。
2. **只改锚点,不改像素。** 拖动写的是规范表字段(`origin`/`deco`),派生几何仍由 `menuLayoutPure()` 算。这与"拖到绝对坐标"的通用布局编辑器根本不同——本项目的行高、行距、等宽、角深都是**算出来的**。
3. **唯一出口是 `balance.json`。** 导出的段粘进 [`public/config/balance.json`](../public/config/balance.json) 的 `menuLayout` 键,保存 → 刷新即生效(与策划热调共用同一通道)。

## 手柄设计法则

几何是派生的,所以手柄不是"物体的把手",而是**字段的把手**。四条法则(实现与注释在 `labModel.ts` 头部):

| 法则 | 含义 |
|---|---|
| 手柄压在**该字段直接决定的那条边**上 | 雅可比 = 1,拖 1px = 字段 ±1 |
| 一个字段只装一个手柄 | 选"随该字段单调移动"的那条边;底锚块的高度绑**顶缘**(底缘恒等) |
| 雅可比 ≠ 1 的写明倍率 | 标签上显示 `×2`/`×6` 等:`endlessW`、`chipH`、`badgeSize`、`makeupH`、`sectionTextPad` 为 ×2,`entryGap` ×6,`setGap` ×3 |
| 依赖**文字测量**的锚点不做手柄 | 筹码宽/星数/钻石图标/通关勾…只给面板数值框。假锚点比没有锚点更坏 |

重合的锚点沿**自由轴**错开 13px 显示,不改变绑定字段。当前环境约 59 个可拖手柄 / 113 个字段(手柄数随标题条开关与缺图状态变化)。

## 操作

| 动作 | 效果 |
|---|---|
| 拖动白点 | 改绑定的锚点字段;按住 Shift 以 **10px 为量化步长**吸附 |
| 方向键 ←→↑↓ | 选中手柄 ±1px(Shift ±10) |
| Esc | 取消选中 |
| 面板字段行 | 点击行 = 选中对应手柄(若有);`+ / −` 按步进微调;`↺` 恢复该字段默认 |
| ◆ / · 标记 | ◆ = 已偏离默认值;· = 与默认一致 |
| 搜索框 | 按字段名或区块筛选(`set` / `band` / `gap` …) |

拖动只影响**绑定轴**,垂直方向的位移被忽略(避免斜拖时误改另一个字段)。

## 视图控制

- **虚拟屏高**:数字框 700~1400,附 `996` / `1246` 两个快捷按钮。宽度恒 560(设计空间),高度按真机屏比伸展;把这两个极值都过一遍再定稿。
- **图层开关**:`布局框`(黄=实际绘制矩形)/ `命中框`(青=热区)/ `参考带`(对齐基线)/ `标签`。
- **模拟缺图**:9 张主菜单底板(`title_plate` `strip_plate` `chip_plate` `section_strip` `row_plate` `row_plate_current` `set_plate` `set_plate_selected` `note_plate`)。布局每帧重算,勾选即时生效,用于验证"美术没到位/加载失败"时的纯代码回退形状。
  - 勾选 = 从 `assets.loaded` 卸掉该图;**真没加载完成的键会被自动禁用**(视觉上等同缺图,但没有图可卸),取消勾选也只加回自己卸掉的键,不会伪造"已加载"。就绪状态是异步的,所以这个禁用判定每帧比对一次签名后再刷新,而不是一开始建面板时定死。
  - 与结构树的三态协调:键被 `menuSkin.hidden` 隐藏或本地预览生效时,对应开关同样置灰禁用(悬停提示区分三种来源),避免"配置隐掉的图又被手动卸/装"造成状态混乱。

## 结构树 · 皮肤(menuSkin)

面板中部的「结构树」按绘制序列出 7 面板 13 层(标题横幅/货币条/筹码/分区标题条/关卡行/套组卡/说明板;除货币条只有图层外各图+文两层)。**拓扑固定**:这里只能操作既有图层,图层增删需重写 `drawMenu`,不在布局台范围内。面板头显示绘制序(`绘制序 N · 只读`)——层级顺序不提供重排。

| 控件 | 语义 | 落点 |
|---|---|---|
| 图层显隐勾选 | 图 = 整层全部资产键进 `hidden`(走缺图契约,回退纯代码形状);文 = 面板进 `textHidden`(图与热区不动)| `menuSkin.hidden` / `textHidden`,**运行时真生效** |
| 换图下拉 | 资产键 → 资产键映射;选回自己 = 删除映射 | `menuSkin.remap`,**运行时真生效** |
| 📁 文件钮 | 本地任意图即时预览(`devOverride`),行尾亮「仅预览」徽标,× 撤销 | **仅布局台内存,刷新即失,绝不进导出** |
| 四边间距 `t r b l` | 面板级加性增量 ±100(取整);叠加在 `deco` 派生的基准值上,**不移动区块、不碰热区** | `menuSkin.insets`,运行时真生效 |
| 图层名输入 | 自定义层名(清空恢复默认)| `menuSkin.layers`,运行时仅透传保存 |

要点:

- **insets 与 deco 是加性关系**:`deco` 仍是唯一基准事实源(布局字段面板照旧),insets 只表达"相对基准再挪多少"。消费映射(每面板 l/r/t-b 各落在哪些派生字段)见 [`CONFIG-TABLES.md`](./CONFIG-TABLES.md) 的 `menuSkin.insets` 表。insets **没有手柄、不进 113 字段清单**——几何是派生的,这条硬约束不因皮肤放宽。
- **换图双通道**:下拉 = 写 `remap`(进配置,浏览器+微信同源生效);📁 = 只换当前会话的显示(给"先看效果再决定要不要换"用)。两通道互不干扰,预览键会在缺图开关行同时标注。
- 空皮肤导出 = `{}` → 合并导出里省略 `menuSkin` 段,与"默认零画面变化"铁律一致。

## 派生量(不可直接编辑)

面板"派生量"区显示 `rowH × gap`、`rowMargin`(九宫格角深)、`listY / 列表下界`、`entryW`、`setW`、`sectionW`、`setBand / noteBand`、`noteCap / noteMaxW`、`setY / 卡底 / 屏底`。**改锚点时盯这里**,不要试图在 JSON 里写这些值——它们在表里没有字段,写了也不会生效。

## 草稿与导出

| 按钮 | 语义 |
|---|---|
| 复制 | 复制当前导出文本 |
| 保存草稿 | 把当前改动写进本地草稿;**改动只在这一步才落盘** |
| 重读 balance.json | 重新拉配置(会覆盖内存值,并标记未保存);闪条显示 `warnings N` |
| 全部复位 | 内存值回到规范表默认——标记未保存,点「保存草稿」才持久,否则重进页面仍恢复旧草稿 |
| 丢弃草稿 | 删 localStorage 草稿;**内存值不变,重进页面才生效** |
| 导出全部字段 | 默认只导出偏离项,勾上后 113 项全出 |

草稿存 `localStorage['lab.menuLayout.draft']`(`{logicalH, vals, skin}`)。**保存门**:拖拽/按键/改字段/皮肤编辑等所有改动只实时更新画面,不写草稿;导出区出现「● 有未保存的改动」提示,点「保存草稿」才落盘;不保存关掉页面即丢。重进页面自动恢复已保存的草稿(皮肤走加载器同款校验通道)。

导出是**合并格式** `{menuLayout?, menuSkin?}`:布局只导偏离项(或勾选全量),皮肤经白名单序列化,空皮肤段自动省略;直接整体粘进 `balance.json` 对应的两个顶层键即可。「重读」与「全部复位」按钮同时管布局与皮肤(复位 = 布局回规范表默认 + 皮肤清空)。

> 越界口径与热调通道**有意不同**:`balance.json` 里的非法值 → 回退默认并告警;布局台拖到边界 → **钳到边界**(不跳回默认)。目的是导出结果永远不会被加载器拒绝。

## 加一个可调字段时

1. 在 `src/data/layoutMenu.ts` 规范表加字段(带四要素备注)+ `MENU_LAYOUT_DEFAULTS` + `MENU_LAYOUT_RANGE`(或 `..._DECO_RANGE`)。
2. `src/ui/menuLayout.ts` 的 `menuLayoutPure()` 消费它,派生几何保持派生。
3. 布局台自动出现面板行(字段清单直接读规范表的键序,声明顺序 = 面板顺序 = 导出顺序)。只有需要**视觉锚点**时才在 `labModel.ts` `buildHandles()` 里加手柄,并按上面四条法则决定绑哪条边、倍率写进 `bind.scale`。
4. 跑 `npx vitest run tests/layout-lab-model.test.ts`——其中的差分用例对每个手柄验证"字段 +1 → 该边恰好移动 |1/scale| px",4 种屏高环境全覆盖。
