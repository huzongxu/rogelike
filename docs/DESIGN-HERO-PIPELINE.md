# 英雄设计流程（身份 → 动词 → 套件 → 带宽 → 门）

> 状态：2026-09-17 定稿。两条裁定打底：① 英雄差异的主轴 = **站位有增益**（不加战场按钮：挂机照样通，玩家控制的相对位置有可测报酬）；② 单个英雄的强弱**不由"深度"单指标判定**，改由 §3 六项口径判定，且每个英雄各自有一条**目标带宽**。
> 进度：**R18 / R19 薇拉那一版已落地**（荆棘层 + 姿势 + 状态型续航 + 分岔代价 + 盾面读数 + 节律简述）；**R20 升级层只剩独有技能与节律**（删「重置分岔」与「补给」兜底，没牌就不开层）、**每关缩到 15 章**（章型重排 4/8/12 与 6/10）；**R21 第 7 步「呈现收口」补完**（出战英雄看得见自己那套与两档效果 + 「本套计件」清单）；**R22 姿势搬到局首二选一**（三档收两档：站定 / 绕场，贴身是共有前提；不再挂分岔）+ **候选① 给"贴身"加短接触记忆**（`THORN_STACK.contactEchoDecayPerSec`，怪刚被清掉也算这一拍；站定档层均 1.62 → 2.13、饿死秒占比 41% → 33%，但两态结局仍不对等，见 §5.2 / §5.5）。六项读数的尺子随之变：判"打得满一关"看 `wave ≥ 15`，目标带宽要按 15 章制重设；取消兜底那口奶让全员通关局数从 31/36 掉到 20/36（归因见 §4），补差路线等用户定夺。**另一条待裁定的不是数值而是缺陷**：`nearestEnemy` 的距离闸把线性距离和 `range²` 比（三道闸的实际半径变成 12100 / 90000 / 102400px），修好它站定档立刻与绕场齐平、其余 11 英雄整体变难、战斗指纹要重签（§5.5 末行）。**V1.1（2026-11-10）**：薇拉 / 凯尔 / 薇洛三原型加章节节点层（第 2 章选支 + 4/8/12 节点），合同见 [DESIGN-HERO-BUILD](DESIGN-HERO-BUILD.md)；矩阵的 8 组合带宽待复量。
> 分工：本文件 = 怎么做英雄、怎么判强弱；[DESIGN-HERO-RHYTHM](DESIGN-HERO-RHYTHM.md) = 已定的三层结构（节律 / 独有技能 / 法宝）与裁定史 R1–R23；[TODO-HERO-RHYTHM](TODO-HERO-RHYTHM.md) = 唯一待办面；数值纪律沿用 [DESIGN-VALUES-SPEC](DESIGN-VALUES-SPEC.md)。
> 范例：§5 薇拉卡 v2 —— 流程的每一步都在她身上走了一遍。`S/` = `cocos/assets/scripts/`。

## 0. 用户画像 → 四条取舍

目标用户 = 弹壳特攻队 / 吸血鬼幸存者 / 土豆兄弟 / 元气骑士 的玩家合集。四款各取一条、各拒一条：

| 参考 | 采纳的那一条 | 在我们仓库的落点 | 明确不采纳 |
| --- | --- | --- | --- |
| 吸血鬼幸存者 | **武器即身份**；进化配方是复玩的知识本体 | 核心技能 = 身份的执行器；共鸣变形 = 配方；发现横幅 = 时刻 | 200+ 武器池；英雄强弱悬殊不做管控 |
| 弹壳特攻队 | **可读性优先**：每层成长都能在界面上看到数 | 卡面一句话几何、HUD 节律进度条（R15）、共鸣进度有满格点（工作树的 `resonanceProgress`） | 局外装备数值压过局内构筑（收藏加成已有此风险，封顶不再加深） |
| 土豆兄弟 | **英雄 = 一条改规则的陈述句**，且句子自带代价 | 身份句必须写成"条件 → 报酬，但收走 B"（§1 第 2 步） | 纯属性向量差异（自动战斗下玩家读不出来） |
| 元气骑士 | **相对位置有反馈**：绕开正面、贴身有风险回报 | §2 站位语义；`shieldguardDamageMult` / 弹体命中点 / 地面无视正面 | 房间制与强制手动翻滚（与单手碎片场景冲突） |

一句话定位：**弹壳的可读数值 + Brotato 的一句话英雄 + VS 的发现时刻，操作强度守在"挂机可通、走位有增益"这一格。**

## 1. 七步流程（每步的产物、落点与禁止项）

| 步 | 做什么 | 产物 | 落点 | 禁止项 |
| --- | --- | --- | --- | --- |
| 1 矩阵定位 | 先问池子里哪一格是空的：节律(6) × 风险偏好(苟 / 换血 / 爆发) × 距离带(贴 / 中 / 远) × 甜点·天敌 | 一行空格声明 | §4 矩阵表 | 用"再出一套技能"代替定位 |
| 2 身份句 | 一句**带代价**的规则陈述，玩家能原样复述 | 一句话 | `heroes.ts` 的 `lore` + `heroSkills` 各 `desc` | 写不出代价 = 这一格还没设计完；"更帅"不是身份 |
| 3 动词检查 | 玩家这一局重复做的那个动作是什么；`autoMove` 接管后还剩多少 | 动词 + 残余操作 | `rhythm.ts` 的 `RHYTHM_AI_PROFILE` / `AI_PROFILE_PARAMS` + §2 几何声明 | 让身份动词在挂机档里归零 yet 靠数值代偿 |
| 4 套件接线 | 核心 = 身份的执行器；分岔 = 两枚**代价相反**的赌注；进阶 = 改写核心的一条规则；共鸣 = 发现时刻；三原型另加 4/8/12 三层节点 = 把主循环改出 8 种组合 | 4 条技能 + 2 条共鸣（+ 6 个节点） | `heroSkills.ts`、`heroBuild.ts` | 分岔两条都朝同一方向变好；节点两层都更好 = 决策不存在；每条只写"+X%" |
| 5 带宽声明 | 把身份翻译成一条曲线：目标深度带 + 目标方差 + 甜点/天敌章差 + 剖面形状 | 一行带宽 | §4 矩阵表 + `balance-sim` 断言 | 把"越深越好"当目标 |
| 6 度量 | 跑 §3 六项，全绿才谈调优 | 六张读数 | `scripts/balance-sim.ts`（`trace` / `forceBranch`） | 只看一个种子或只看均值 |
| 7 呈现收口 | 身份句要在 3 秒内被读到：英雄页五行（含「套装」行：套组名 + 两档联动效果全文）/ 卡面 / HUD 条 / 商店段 | 三处文案 | `heroes.heroSkillLines`、`HudView`、`ShopView` | 机制成立但界面上读不出来 |

第 5 步是本流程的分水岭：**数值的作用是把英雄翻译成一条有起伏的曲线，而不是把一个数字推到上限。**

## 2. 站位语义（主轴的具体落点）

结算层里**已经存在**四道与"伤害从哪里来"绑定的判定，站位增益不需要新原语，需要的是每个英雄声明自己站在哪一格：

| 几何 | `damageEnemy` 的 `from` | 对盾卫 / Boss 的正面减伤 | 代价 |
| --- | --- | --- | --- |
| 自身中心（新星、霜环） | `p.pos` | **恒吃**：`FRONT_GUARD_DOT 0.5`（正面 60° 弧）+ 盾卫 `0.2×` / Boss `0.6×`，因为盾卫与 Boss 的 `facing` 就是朝向玩家 | 覆盖最稳，换走的是"打硬目标打折" |
| 来袭者脚下（`castAtAttacker`） | ≈ 敌人自身，点积退化到 0 | **不吃** | 只打得到刚才打我的人，丢开环外那圈 |
| 弹体（knife / ray / icelance） | `proj.pos`（命中瞬间） | 绕到敌后那一发是全额 | 受几何命中率、隐身与吞噬影响 |
| 地面（cloud / 熔迹 / 荆棘带） | tick 不传 `from` | **天然无视** | 延迟结算，要求玩家把敌人留在地上 |

另外两条与站位无关、只能靠 build 特効解的：隐匿者隐身段不可命中（`HIDER_CYCLE 5` / 可见 3）、吞噬者吸弹（第 6 章起，洛卡 R16 的 `slayDevourer` 即此层的解）。

站位收益的登场窗口也是确定的：第 6 章起 `SPAWN_CURVE` 刷 shieldguard ≈5%、reflector ≈6%、devourer ≈6%、summoner ≈8%，第 20 章是 Boss（正面 0.6×）。**所以"英雄有没有性格"最有效的观察带就是第 6–20 章。**

流程上要求两件事：

1. 每个英雄的四件套必须能归到上面某一（几）格几何，并写进 §4 矩阵；
2. 界面上要有读数：正面被挡已有 `emitShieldBlock` 火花，但玩家看不到"我这一圈全打在盾面上"——这条挂在本流程第 7 步。

## 3. 六态度量表（判据）

口径固定为**真机口径**：`runSim({ chapterReset: true, chapterTypes: true, shopGrowth: true, maxSeconds: 1200, trace: true })`，种子 21 / 123 / 7。

| # | 度量 | 取数 | 门槛 | 为什么是它 |
| --- | --- | --- | --- | --- |
| 1 | 首章存活 | `trace` 前 60s | 硬门，三种子全过 | S1-c 既有验收项，防冷启动死锁（R6 的教训） |
| 2 | 深度带 | `report.wave` 均值 | 落进该英雄的目标带（**不是越高越好**） | 均值是唯一的跨英雄可比量 |
| 3 | 种子间方差 | 三种子的极差 | 性格型（换血 / 站桩）≥ 4 章；稳定型（周期）≤ 3 章 | 方差就是"有脾气"的可测形式 |
| 4 | 甜点 / 天敌章差 | `trace.ch % 4` 归属敌情（1 尸潮 / 2 重甲 / 3 异变 / 4 精英）+ 死亡章号 + 各敌情章的每秒净掉血 | 甜点章均值 − 天敌章均值 ≥ 5 章，且方向与 §4 声明一致 | 敌情系统的克制导向目前基本是文案，机制上没兑现 |
| 5 | 分支差 | 同种子 `forceBranch` 各跑一遍两枚分岔 | ≥ 3 章，且**两条各自在别的敌情上吃亏**（同向差不算成立） | 分岔互斥是一局最重的决策，差值被噪声吃掉 = 决策不存在 |
| 6 | 剖面形状 | `trace` 的 HP / 围数峰 / 承伤 / 回血 / 技能与法宝伤害占比 | 换血型 HP 波动带 ≥ 40% maxHp；风筝型 ≤ 20%；核心几何的伤害占比 ≥ 50% | 深度到顶的英雄只有这一项还有分辨率（薇拉即此例） |

读数纪律：**六项都有数才算可调**；只报深度等于碰运气。任何一项跑不出来就在 TODO 里记工具缺口。

## 5. 薇拉卡 v2（范例）

### 5.1 身份句（带代价）

**挨打即爆发——但你这一圈只能打正面，血也只认"还站在里面"。**

- 报酬：受击 → 荆棘圆环（`nova` 伤 50 / 半径 200，`hitCd 0.7` ≈ 被围时最高 1.43 发/秒）+ 受击系 ×1.5 增伤 + **荆棘层**（贴身才涨：满层半径 +36%、每秒回 6 血，血棘再 +4）；
- 代价（四条，全部来自既有结算）：
  1. 核心以自身为圆心 → `from = p.pos`，而盾卫与 Boss 恒面向玩家 → 对盾卫 **0.2×**、对 Boss **0.6×**，第 6 章起与第 20 章固定吃这口；
  2. 大范围多目标 + 受击系 ×1.5 → 反射者（25% 反弹，每秒预算 15% maxHp）把伤害还给她比还给任何单体流都多；
  3. 层数掉了就同时失去半径、威力与回血 —— 续航不再是"挨一下就回一口"，而是"留在危险区才有的报酬"；
  4. 输出与生存仍同源于"贴身"这一件事，但**它现在有价格了**：站进去要掉血，退出来要断奶。

> R19 之前的第 3 条不成立：她的两条回复（挨打回 2% / 棘肤回 1.5%，都按最大生命比例）与商店的全局吸血被动叠成"越肉越奶"，实测每秒承伤 7–30 对回血 60–120 → 四种敌情全净回血，天敌根本不成立。现在两条比例回血对走荆棘层的玩家停用（棘肤那一档改成层数倍率 ×1.5），她的续航只剩"层数 × 每秒速率"这一条可钳的通道。

**由此得出一条文案缺陷**：`intel.ts` 把「异变」（分裂体 + 反射者）的推荐套组写成荆棘，而反射者恰恰是她的天敌。要么改推荐，要么改她的几何让她有解——推荐后者，因为那正好是分岔该干的活。

### 5.2 动词与残余操作

动词 = **决定什么时候站在圈里**，并且**决定用哪种姿势站在圈里**。裁定走"站位有增益"之后，这个动词不需要按钮，层数就是它的读数：

| 姿势 | 攒层条件 | 什么时候定 | 自动档 |
| --- | --- | --- | --- |
| 站定 | 贴身 **且本帧没动** 才涨 | **局首二选一**（表首项 = 没走到弹层时的兜底档） | `hold`，但**取消"围到 4 只就跑"**（那等于让这档自相矛盾），只保留血量线 |
| 绕场 | 贴身 **且在动** 才涨 | **局首二选一** | `orbit`（持续绕场，敌人很近才躲） |

两态共用同一个距离闸与同一套涨落常数（`combat.THORN_STACK`），**"贴身"是两态共同的前提**，姿势只决定还要不要"停"或"走"；层数同时驱动半径、威力与回血 —— 所以"姿势"不是标签，是两条互斥的身体。挂机档由姿势推导（`still → hold`、`move → orbit`），世界层与模拟器同一处口径。

**这条"贴身"前提带短接触记忆**（R22 候选①，用户裁定）：喂层的数是 `THORN_STACK.contactEchoDecayPerSec`（6 围数/秒）衰减出来的 `Player.thornContactEcho`，怪被自己的圆环清掉后按围数正比继续算这一拍（1 只 ≈0.17 秒、3 只 ≈0.5 秒、6 只 ≈1 秒）。理由是稀怪章的怪进闸半秒就死，没有记忆时"贴身"这个前提几乎不成立（站定档"层数为 0 的秒占比"41%）。**姿势那一条没被放宽**：站定仍要求本帧不动、绕场仍要求在动，`cap` 与 `decayPerSec` 也都没动。这一档是"站定的地板"换"绕场的曲线"的旋钮：真机口径每格 120 局量下来，站定层均 1.62 → 2.13、饿死秒占比 41% → 33%，代价是绕场满层占比 41.7% → 54.6%（衰减放到 1 那一档会到 81.7%，强档的涨落曲线就没了，所以没取）。读数上屏在姿势层：读数行「每只死后留 0.17 秒记忆」（由表值算）、提示行与两张卡正文各一句「怪刚被清掉也算这一拍」。

**记忆治不到站定档的结局**：死亡率与章均都留在噪声带里（38→43% / 18.32→18.66 章），两态仍不对等（站定 18.66 章 / 43% 死 对 绕场 20.58 章 / 13% 死）。原因是站定档还有第二条病根，而且它不在数值层 —— 见 §5.5 末行。

**R22 把姿势从分岔搬到了局首**（用户："土豆兄弟的反伤角色设计的更好玩，角色两种状态可以考虑开局选择，不在分路上"）：分岔只管"核心怎么打"（几何 + 数值代价），姿势是开局那一次身份选择，每局重选、两态开局即可用、不可锁不可重随。表 = `heroSkills.VERA_STANCES`，出口 = `heroStances(heroId)`（只有走层数的英雄有），弹层 = `LevelUpModel` 的 `stance` 形态（复用升级弹层那套卡面与闸门，两层串成"先姿势、再首章法宝"）。

其余两条既有的手动报酬：**绕到盾卫 / Boss 侧面或背后再放环**（从 0.6× 回到 1×）与 **把敌人留在荆棘带上**（地面无视正面减伤）。

## 6. 一轮英雄调优的标准作业（SOP）

1. **清点工作树**：`git diff --stat` + 按 mtime 分桶，确认哪些是未提交的在飞改动；在飞部分先复量、不叠加新改动。
2. **复量**：三种子 + `trace`，必要时 `forceBranch` 双支；产出六项读数（一次性驱动脚本留在 `.probe/`，不入库）。
3. **对表**：读数与 §4 的带宽目标比对，判定是"数值偏了"还是"机制没棱角"——后者不允许用数值治（洛卡 R16、穆 R17 都是这条判据下改的机制）。
4. **改表**：只改 `S/game/data/*`，四要素注释（含义 / 单位 / 依据 / 代价）同步。
5. **复跑对照**：其余 11 英雄逐位不动是硬要求；有漂移必须能完全归因。
6. **五道门**：`npm test` → `npm run build` → `npm run build:cocos` → `npm run smoke:cocos` → `npm run typecheck:cocos`；战斗指纹若动，按 P6 单独签字。
7. **真机剖面**：无头 Edge + CDP 跑构建包，抓一条能证明身份句的静帧 / 读数（每条探针换 user-data-dir）。
8. **文档三处**：TODO 删行或加行、`DESIGN-VALUES-SPEC` §四登记新表值、`CONTEXT` 加一条落地记录。

## 7. 纪律

- **深度不是目标值，带宽才是。** 顶到 21 的英雄等于没有目标。
- **每个英雄必须有一条天敌和一个打不了的仗**；没有天敌的英雄等于没有性格。
- **分岔必须关一扇门**，两枚都更好 = 决策不存在。
- **节点同样必须互斥且各自关一扇门**：第 4/8/12 层两层都更好 = 这一层没有决策；节点不占升级槽 / 商店槽 / 共鸣计数，但必须能在第 15 章前兑现。
- **不加战场按钮**（现有定位：战斗 HUD 无操作钮）；玩家的增益只走相对位置与构筑选择。
- **机制病不用数值治**：先跑剖面定位结算分支，再决定改表还是改机制（R14 三杠杆全在噪声内即此教训）。
- **反哺 / 层数类资源必须有总量上限与释放速率约束**（穆 R17 的 runaway 教训）。
- 改数值一律入表并跑 `npm test`；`.probe/` 全目录不入提交。
